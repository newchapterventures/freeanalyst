# FreeAnalyst 部署形态

> 用户 2026-09-18 的原话：
> 「类似于一个 app，用户下载到本地，然后再适配相应的开源大模型。**如何部署呢？**」

## 一、先定形态：三层，同一套代码

```
                    ┌─────────────────────────┐
   开发者            │  pip install / docker    │   ← GitHub 开源用户
                    └─────────────────────────┘
                    ┌─────────────────────────┐
   普通用户          │  下载 .dmg / .exe        │   ← 一键，不碰终端
                    └─────────────────────────┘
                    ┌─────────────────────────┐
   模型              │  探测本机已有的          │   ← **模型不进安装包**
                    └─────────────────────────┘
```

**三层是同一套 Python 代码**，不是三个产品。区别只在**怎么启动**。

## 二、关键决定：模型不进安装包

开源模型动辄 5–20 GB，**打进安装包是灾难**：下载慢、更新烦、显卡适配还要另说。

正确做法：**安装包里没有模型，但会自动找本机已有的。**

```
探测顺序
  1. ollama          http://127.0.0.1:11434     ← 最常见
  2. 任何 OpenAI 兼容的本地服务  http://127.0.0.1:1234
     （LM Studio / vLLM / llama.cpp server 都是这个协议）
  3. 都没有 → 不报错，降级
```

用户在 LM Studio 里点两下、或者 `ollama pull qwen3:14b`，这个工具就直接用上了。

## 三、**没有模型也能用** —— 这条决定了部署的宽容度

这个工具里：

| 功能 | 靠什么 | 没模型时 |
|---|---|---|
| 提取三张表 | 纯代码（正则 + 版面分析 + 本机 OCR） | **照跑** |
| 口径判断 | 纯代码 | **照跑** |
| 财务勾稽校验 | 纯代码 | **照跑** |
| 可比公司取数 | 结构化接口 | **照跑** |
| **估值计算** | **纯代码算，不用 LLM 算**（项目纪律） | **照跑** |
| Football Field | 纯代码 | **照跑** |
| 读材料回答问题 | 大模型 | 不可用 |
| 从业务描述提行业建议 | 大模型 + 关键词表 | 降级到关键词表 |

**所以「装不上模型」不是装不上这个工具。** 这一点很重要 ——
它意味着部署的第一版不用等模型适配，先用起来是可行的。

## 四、装完先过质量门槛（用户明确要求）

> 「鉴于开源大模型参数少，我们要保证开源大模型达到我们想要的结果。」

小模型能让流程跑通，但会犯三类**致命**错误：

1. **主体搞混** —— 把实控人的个人回购义务说成公司的财务压力
2. **跨文档冲突检测不出来** —— CIM 说条款已定，访谈纪要里对方其实有保留
3. **编造内容** —— 材料里没有的文件，它替你把结论写出来

这三类在尽调里会**直接导致错误结论**。所以门槛不是「越强越好」，
是**这三类错一个都不能犯**。

```
freeanalyst.py models                    看有哪些模型可用
freeanalyst.py models --gate qwen3:14b   对这个模型跑门槛
```

判分逻辑只有一份，在 `bench/model_quality.py`；门槛层只做**调度和裁决**，
不重复实现判据 —— 免得两边不一致，出现「bench 说够格、门槛说不够格」。

**没一个模型够格时怎么办**：不是「先凑合用」，而是
**只用不需要模型的功能**（提取 + 校验 + 估值全都能跑）。

### 一条自检规矩

换判据之前先拿**已知不合格的模型**跑一遍 ——
**如果它全过，说明评测失效了**，不是模型变强了。

## 五、部署路线（按顺序做，每步都能独立用）

### 阶段 1：源码运行（现在就能用）

```bash
git clone https://github.com/newchapterventures/freeanalyst
cd freeanalyst
python3 freeanalyst.py doctor          # 自检
python3 freeanalyst.py models          # 看模型
python3 tests/test_egress_guard.py     # 验证「零出境」是真的
```

**面向**：能读 README 的人。开源仓库的标准形态。

### 阶段 2：本地网页（把界面搭起来）

后端起一个只听 `127.0.0.1` 的本地服务，浏览器打开 `localhost:PORT`。

```
FreeAnalyst.app
 ├─ 后端  FastAPI on 127.0.0.1:8765   ← **只绑回环，不绑 0.0.0.0**
 └─ 前端  浏览器自动打开
```

⚠️ **必须只绑 `127.0.0.1`**，不能绑 `0.0.0.0` —— 绑了 `0.0.0.0`
同一个 WiFi 下的任何人都能访问你的尽调材料。这条要写进测试。

### 阶段 3：Docker（一条命令）

```bash
docker run -p 127.0.0.1:8765:8765 \
  -v /path/to/materials:/data:ro \
  freeanalyst/freeanalyst
```

要点：

- **`-p 127.0.0.1:8765:8765`**，不是 `-p 8765:8765`（后者会暴露到局域网）
- **材料用 `:ro` 只读挂载** —— 工具不该改用户的原始材料
- 模型**不在容器里**：`--network=host` 或让容器访问宿主机的 ollama
  （容器网络访问宿主机 ollama 要处理 `host.docker.internal`）
- 镜像里**不带模型**，所以体积可控

### 阶段 4：打包成原生 app（面向非技术用户）

| 平台 | 打包方式 | 产物 |
|---|---|---|
| macOS | PyInstaller 包后端 + Tauri/pywebview 包界面 | `.dmg` |
| Windows | 同上 | `.exe` / `.msi` |

要点：

- **捆绑 Python 和依赖**（用户不用装 Python），**不捆模型**
- 首次启动做一次 `doctor`，把结果直接显示在界面上
- macOS 要签名+公证，否则用户双击会被告知「已损坏」
- **体积估算**：Python + 依赖约 150–250 MB，加前端约 300 MB。
  加上模型（用户自己下）才是 GB 级

## 六、为什么是这个顺序

**阶段 1 现在就能用** —— 不用等界面。界面是「好用」，不是「能用」。

**阶段 2 是价值最大的一步** —— 它把「要敲命令」变成「点开就能用」，
也才让三个互动环节（确认行业 / 挑可比公司 / 定假设）真正落地。

**阶段 3 解决开源用户的安装摩擦** —— GitHub 上的人不介意 Docker。

**阶段 4 面向真正的目标用户**（不碰终端的人）—— 但它最贵：
签名、公证、跨平台、自动更新，每一项都是持续维护成本。
**在阶段 2 被验证之前不该做。**

## 七、要一起想清楚的几件事

| 问题 | 现在的倾向 |
|---|---|
| 分析结果存哪 | 用户的材料目录旁边，命名 `<材料目录>/.freeanalyst/`；**默认不进用户的其他目录** |
| 多项目怎么办 | 一个项目一个目录，工具不建全局数据库（用户能直接看到自己的数据在哪） |
| 模型换了，历史分析怎么办 | **分析结果里记下用的模型和版本** —— 换模型等于换了一种判断，要能追溯 |
| 更新怎么推 | 阶段 1/3 靠 git pull / 新镜像；阶段 4 要有自动更新，否则用户会卡在旧版 |
| 怎么证明没出网 | `tests/test_egress_guard.py` 会拿 OpenAI / Anthropic 的真实地址去撞，撞通了就测试失败。**用户能自己跑** |
