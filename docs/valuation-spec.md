# 估值模块需求基线

> **这份文件的作用**：以后每加一个功能，对照它检查有没有漏。
>
> 它记的不是"我们要做什么功能"，而是"**什么情况下这个估值才是可信的**"。
> 功能可以增删，这些条件不能绕过。
>
> 状态：v0.2 基线。最后更新 2026-09-15。

## 1. 场景声明（Step 0）—— 不填不算

**这是整条流程的第一道门。** 这六项不定，方法无从选，结果也无意义。

| 字段 | 取值 | 为什么必须 |
|---|---|---|
| **估值目的** | 融资定价 / 并购定价 / 投后NAV / 税务合规 | 同一份三张表，目的不同，方法和口径完全不同 |
| **立场** | 买方 / 卖方 / 中立 | 买方保守、卖方激进，同一个模型假设取向相反 |
| **标的发展阶段** | 早期项目 / 成长企业 / 成熟企业 / 业主经营 | 决定哪套方法可用（见 §5） |
| **基准日** | 日期 | 多期数据必须在此日期对齐 |
| **货币** | CNY / USD / HKD / … | 决定无风险利率、税率、汇率基准 |
| **权益范围** | 100% / 少数股权 x% | 决定要不要控制权溢价或少数股权折价 |

**实现状态**：`valuation/core.py::Scenario` ✅

## 2. 架构分层

```
L0  原始材料
    ├─ 上市公司年报（XBRL / PDF）
    ├─ 三张表（Excel / CSV）
    └─ 自然语言描述
         ↓
L1  结构化 + 行级理解
    ├─ 科目本体（CAS / US GAAP / IFRS / HKFRS）
    ├─ 科目映射（财报原始行名 → 标准科目）
    ├─ 勾稽校验（§4.5）
    └─ 准则标注
         ↓
L2  跨准则可比性（先标注，后调整）
         ↓
L3  外部参数（联网 · 公开域）
    ├─ 税率（所得税 / 增值税 / 附加 / 优惠）
    ├─ 贷款利率（LPR / SOFR + 行业利差）
    ├─ 可比公司 multiples
    └─ 行业 benchmark
         ↓
L4  估值引擎（纯代码）
         ↓
L5  输出：区间 + 追溯 + 敏感性 + 缺口 + 假设参谋
```

### 2.1 能力隔离边界 —— v0.2c 已实现

**L1/L2 处理机密财报，没有联网能力；L3 联网，拿不到机密数据。**

这条不是设计偏好，是"数据零出境"在新架构下的唯一可证明形式。

#### 为什么不用内容过滤

因为做不到。你无法判断一段出境文本里有没有夹带机密：

> "标的企业A、收入1.83亿、增速17.9%、行业只有三家可比"
>
> 这组数字本身就是指纹，把公司名替换成"A"没有用。

#### 三层防护（按重要性排序）

| 层 | 机制 | 强度 |
|---|---|---|
| **1. 代码路径隔离** | 公开域函数只接受代码/日期/指标名，调用点写在读不到语料的代码里 | **根本保证**。不靠检查，靠结构 |
| **2. 语料重叠检查** | 出境值与本地语料逐字比对，重合即拒（归一化后比对，改写标点绕不过） | **主防线**。确定性、可验证 |
| **3. 格式检查** | 长度、字符集、换行、本地引用模式 | 防误伤，**不是主防线** |

#### 格式检查被实测证明不足 —— 这条要记住

```
样本                     长度   格式检查结果
完整段落（45 字）         45     ✗ 通过了
财务句（53 字）           53     ✗ 通过了
短句（24 字）             24     ✗ 通过了
```

原因：语料句子混着数字和标点，中文串被打断，"连续中文超过 N 个字就拒绝"
这类规则触发不了；而放宽长度上限会连正常查询一起拦掉。

**`tests/test_public_egress.py` 里有一条测试专门把这个局限固定下来**
（`TestFormatChecksAreNotEnough`），防止后来的人以为格式检查够了。

#### 禁名表

**标的公司的名字本身也是机密** —— 不能让人从查询日志里看出你在看哪家公司。
禁名表从 `root/privacy-blocklist.txt` 读取（在 .gitignore 里，属私有资产）。

合规的替代查询方式：**用行业代码，不用公司名**。
查 `C3670` 而不是查 `宁波精塑`。

#### 审计日志可公开

公开域的审计日志记下的只有公开查询词，**所以这份日志可以直接展示给人看** ——
这才是"数据不出境"在新架构下的可证明形式：不是承诺，是一份可核查的记录。

**实现状态**：✅ `net.py`（公开域闸门）+ `privacy.py`（跨域防护）+ 22 项测试

## 3. 五步流程

```
Step 0  声明场景（§1）
              ↓
Step 1  取得财务基础
        ├─ 有表 → 四道校验（§4）→ 过不了就停
        └─ 无表 → 解析财报与业务规划 + 对话补齐 + 网络 comps
              ↓
Step 2  构建假设
        ├─ 用户给假设
        ├─ 系统给对照系（§7）← 产品价值所在
        └─ 标注每个假设的置信度
              ↓
Step 3  输出数据缺口清单（§6.4）← 强制，不是可选
              ↓
Step 4  计算（纯代码）
        ├─ 正向：DCF / Comps / 先例交易 / 早期方法
        └─ 反向：从价格反推假设（§6.6）
              ↓
Step 5  输出（§6）：区间 + 追溯 + 敏感性 + 缺口 + 与用户对话
```

## 4. 输入校验 —— 四条硬规则

**有现成的三张表，不等于可以直接用。** 过不了以下任意一条，必须停下并要求补充。

### 4.1 准则口径

| 准则 | 关键差异 |
|---|---|
| **CAS**（企业会计准则） | 研发支出：研究阶段费用化、开发阶段满足条件**资本化** |
| **小企业会计准则** | 境内另一套科目体系，**小公司大概率是这套**，与 CAS 不可直接比较 |
| **US GAAP** | 研发支出**全部费用化**；企业合并用控制性财务利益模式（VIE/VOE）；金融资产无整体分类 |
| **IFRS** | 同一控制下业务合并**无明确规定**，企业自定政策 |
| **HKFRS** | 港股可选 CAS / IFRS / US GAAP / HKFRS 四种，必须先确认用的是哪种 |

**处理顺序**：先**标注**（这个数字是哪个准则口径），后**调整**（换算到统一口径）。
调整需要会计专业输入，不由引擎自行判断。

### 4.2 合并口径

**合并报表 vs 母公司报表，同一家公司的同一个科目能差一倍。** 必须明确标注。

### 4.3 审计状态

**未审数据不能直接进模型。** 若必须使用，需在输出中显著标注。

### 4.4 期间对齐

自然年 vs 财年、月度 vs 季度、不足整年的期间。同比计算前必须对齐。

### 4.5 勾稽校验 —— 可验证的成功标准

"理解三张表每一行"是这套系统里最贵的一块，因为会计科目不是确定清单
（公司会自创科目名）。**但勾稽关系给了我们一个客观的、免费的、机器可判定的
质量指标：**

| 校验 | 可判定 | 说明 |
|---|---|---|
| 资产 = 负债 + 所有者权益 | ✅ 精确 | 平不了，说明科目映射有错 |
| 期末现金 = 期初 + 经营 + 投资 + 筹资现金流 | ✅ 精确 | 三张表的连接点 |
| 净利润 → 经营现金流的间接法调节 | ✅ 精确 | 最能暴露映射错误的一项 |
| 科目归属是否正确 | ⚠️ 需抽检 | 用前三项缩小范围后再人工看 |

**平了三张表，说明理解对了。** 这是 v0.2a 的验收标准。

## 5. 方法与适用条件

**方法不是选的，是场景决定的。**

| 方法 | 适用 | 不适用 |
|---|---|---|
| **DCF（FCFF）** | 现金流可预测、经营历史稳定 | 无收入的早期项目 |
| **EBITDA 乘数** | 有正 EBITDA 的成熟企业 | D&A 政策差异大时不调整会失真 |
| **SDE 乘数** | **业主经营的中小企业**（search fund 主场景） | 规模以上企业（所有者薪酬已市场化，无可比性） |
| **收入乘数** | 高增长、尚未盈利 | 低毛利业务（收入不等于价值） |
| **先例交易** | 有可比交易样本 | 交易稀少的行业 |
| **早期方法**（Berkus / Scorecard / VC 法） | pre-revenue | 有稳定现金流的成熟企业 |

### 5.1 SDE 与 EBITDA 是两个口径

| | SDE | EBITDA |
|---|---|---|
| 口径 | 业主可支配口径 | 公司经营口径 |
| 含 | 所有者薪酬按市场水平调整、个人性质费用加回 | 不含这些调整 |
| 用于 | 中小企业并购 | 规模企业 |
| 乘数 | 通常 2–4.5x | 通常 6–12x |

**同一个乘数套到两个基数上，结果能差一倍。** 必须显式声明用的是哪个口径。

**实现状态**：`valuation/multiples.py` ✅

### 5.2 早期项目的三个方法各自回答什么问题

**实现状态**：`valuation/early_stage.py` ✅

| 方法 | 回答的问题 | 本质 |
|---|---|---|
| **Berkus** | 去掉了几个风险？ | 每个风险值一点钱，加起来 |
| **Scorecard** | 比市场上的同类项目好还是差？ | 从区域基准出发做加权调整 |
| **VC 法** | 要赚到目标回报，今天最多能付多少？ | 从退出价倒推 |

**三者的哲学完全不同，所以它们给出不同的数不是错误，是信息。**
差额本身就该写进备忘录。

#### 两个锚点必须显式给，没有默认值

| 锚点 | 为什么不能有默认值 |
|---|---|
| Berkus 的「每因素封顶值」 | 原版是 1990 年代美国西海岸的 50 万美元。**照抄到别的年份、别的地区是错的** |
| Scorecard 的「区域基准 pre-money」 | 是外部事实，不是能从标的材料算出来的。而且**时效性极强**——市场冷热差一年，定价能差一半 |

给这两个数配"合理默认值"是最糟的设计：用户会拿到一个看起来正常的数，
而它其实来自别人的市场、别人的年份。**所以不给就报错。**

#### VC 法里最容易漏的一项是稀释

    今天占 20% ≠ 退出那天还占 20%

后续每轮都会稀释。忽略稀释会让算出来的 pre-money **偏高**，
偏高幅度正好等于被稀释掉的那部分。

**稀释是必然发生的**（只要还要再融资），不是悲观假设。真正的未知只是比例。

另一个反直觉的点：**稀释让投前估值变低，不是变高。**
投资者要 20% 的退出股权，有 25% 未来稀释时今天必须占到 26.67%；
为同样的钱拿到更多股权 → 投后更低 → 投前更低。
这条写反了不会报错，只会安静地给出错的数。

#### 反向法（§6.6 的强制要求）

有报价就必须跑。它把「贵不贵」翻译成「要涨到多大」：

> 按这个价格，公司要在 5 年内做到 24.3 亿的退出价值，即年化 70.2%。
>
> **谈论这个数是否可信，比谈论估值高低有用得多。**

反向结果**不参与多方法差额**（`is_valuation=False`）——它输出的不是估值，
是「需要多大的退出」。混进去算差额会得出一个毫无意义的数，
而且看起来还挺像回事（实测它把差额从合理的量级拉到了 199%）。

## 6. 强制输出项 —— 缺一不可

**这不是"建议提供"，是"不提供就是不合格输出"。**

### 6.1 估值区间，不是单点

单点估值是伪精确。区间来自：敏感性网格极值、多方法交叉、或可比公司分位数。

**实现状态**：✅（`run_dcf(range_grid=...)`、`run_multiples`）

### 6.2 计算追溯

每个结果必须能回答"这个数字怎么来的"。含公式、输入值、来源。

**实现状态**：✅（`core.py::Trace`）

### 6.3 敏感性 —— 哪个假设最影响结果

**没有敏感性的 DCF 是不完整的。** 并且要报出跨度：
跨度超过中值 50% 时，必须明说"单点结论不可靠，谈判应给区间"。

**实现状态**：✅（`dcf.py::sensitivity`）

### 6.4 数据缺口清单 —— 强制

**用户不知道的数据，必须明确列出来，禁止用默认值填掉。**

默认值是估值里最阴险的错误来源：**它不报错，但结果全错。**

桥梁项（少数股东权益、非经营性资产）缺失时，可以按 0 参与计算，
**但必须同时出现在缺口清单里**，并在追溯中标注。

**实现状态**：✅

### 6.5 低置信度假设清单

结果的软肋。来源为"管理层规划""估算""示例值"的，全部列出。

**实现状态**：✅

### 6.6 反向估值 —— 有报价时必须做

对方给了一个价格时，**必须反推隐含假设**。

> "对方要 4.2 亿，这意味着他假设未来三年增长多少？这个假设现实吗？"

正向估值告诉你"我认为值多少"，**反向估值告诉你"对方的价格里藏着什么假设"**——
而后者往往直接就是谈判的切入点。

**实现状态**：✅（`dcf.py::reverse_dcf_growth`，目前支持反推永续增长率）

### 6.7 多方法交叉验证

有 ≥2 种方法时，必须报出**方法之间的差额**。差额本身是信息：
差 30% 说明两种方法对终值/乘数的假设分歧很大，必须解释。

**实现状态**：⚠️ 部分（value.py 有退出倍数交叉验证；football field 可视化未做）

## 7. 假设参谋（v0.3）—— 差异化的位置

**这是这个产品真正的位置。** 竞品都在做"帮你算得更快"，
**没有一家在解决"这个 WACC 到底该填多少"。**

### 7.1 用户给一个假设时，系统该做什么

| 层次 | 动作 |
|---|---|
| 最低 | 接受并计算 → **这是计算器，市面有几百个** |
| 应有 | 给出行业同类公司的**分布**，标出用户假设落在第几分位 |
| 应有 | 给出**历史达成率**：这个管理层过去的预测兑现过吗 |
| 应有 | 列出**支撑这个假设需要什么证据**，以及去哪找 |

### 7.2 假设的对照系

每个关键假设（WACC、增长率、毛利率、EBITDA 率、永续增长）都应配一个对照：

```
假设：2027 年收入增长 14.6%
对照：
  · 同行业上市公司近三年收入 CAGR 分布：P25 6.2% / 中位 9.8% / P75 15.1%
    → 你的假设落在第 72 分位
  · 该公司自身近三年实际 CAGR：17.9%（但主要由 PP 粒子价格回落驱动）
  · 管理层 2024 年做的预测，实际达成率 83%
建议：14.6% 处于合理上沿。但增幅来源需拆开——若主要来自价格而非放量，
      可持续性存疑。
```

**实现状态**：❌ 未开始（v0.3）

## 8. 数据结构约定

### 8.1 假设对象

每个进入计算的数字都必须包成 `Assumption`：

```python
Assumption(
    name="调整后EBITDA",
    value=3860,
    unit="万元",
    source="CIM：报表EBITDA 3,150 + 加回 420/190/100",
    confidence=Confidence.MEDIUM,
)
```

| 置信度 | 来源 |
|---|---|
| **高** | 审计报告、已签合同、官方披露 |
| **中** | 管理报表、可交叉验证的访谈 |
| **低** | 管理层口径、规划目标、行业传闻、**裸数字** |
| **缺失** | 没有这个数 |

**裸数字（没有来源）自动标为「低」置信度。** 这是有意的：没有来源的假设
就是低置信度的假设，不该被当成事实。

### 8.2 缺省值规则

| 类别 | 缺失时 |
|---|---|
| **核心输入**（基数、乘数、净债务、折现率） | **报错，拒绝计算** |
| **桥梁项**（少数股东权益、非经营性资产） | 按 0 计算，**但强制进缺口清单** |

## 9. 术语表 —— 容易混的三组

### 9.1 少数股东权益 vs 少数股权折价

| 术语 | 语境 | 方向 |
|---|---|---|
| **少数股东权益**（non-controlling interest） | 资产负债表科目 | 从企业价值中**扣除** |
| **少数股权折价**（DLOM） | 估值调整 | 对股权价值**打折** |

**方向相反，混了会错两次。**

### 9.2 企业价值 vs 股权价值

```
企业价值 EV ─ 净债务 ─ 少数股东权益 + 非经营性资产 = 股权价值
```

**净债务 = 有息负债 − 现金**（不是总负债减现金）。

### 9.3 投前 vs 投后

融资定价场景必须明确。**投后 = 投前 + 本轮投资额。**

**实现状态**：⚠️ 尚未强制区分

## 10. 反模式 —— 明确不做

| 反模式 | 为什么 |
|---|---|
| **用 LLM 做算术** | 会算错，且算错了查不出来 |
| **静默填充默认值** | 不报错但结果全错，最阴险 |
| **单点估值给结论** | 伪精确 |
| **用没有时点的乘数** | 倍数必须带"什么时候、哪个市场、哪一组可比公司" |
| **混用 SDE 与 EBITDA 口径** | 结果差一倍 |
| **混淆少数股东权益与少数股权折价** | 方向相反 |
| **有报价却不做反向估值** | 浪费了最有用的一个工具 |
| **算不出来时给一个"看起来正常"的数** | 宁可报错 |
