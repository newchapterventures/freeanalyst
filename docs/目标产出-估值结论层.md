# 目标产出：估值结论层

> 这份文档定义**终点**，反过来约束「信息提取要做准」到底指哪些字段。
> 提取层现在的验收标准是勾稽（资产=负债+权益），那是**内部质量检查**，
> 不是用户要的东西。用户要的是下面这些。

## 用户原话（2026-09-16）

> 目前我们做的都是估值相关，我希望可以产出 football field chart，
> 还有各种不同假设下的敏感度分析。这是第一步，后面可以再加。
> **前提是需要先把信息提取这一步做准。** 然后就是不同估值方式的路径，
> 去获取相应的数据，同时**跟用户进行互动，得到相应的不同假设**，
> 根据报表、附录、外部可比公司、行业信息等，能够生成不同情况下的估值数据，
> 并形成各类比较报表，比如刚刚提到 football field 等。

## 三个层次

```
① 提取层    材料 → 三张表 + 股本 + 口径          ← 现在在这里
② 假设层    与用户互动，把「事实」和「假设」分开
③ 结论层    Football Field / 敏感度 / 比较报表
```

---

## ① 提取层：**估值真正要的字段清单**

现在的提取以「三张表 + 勾稽平」为验收标准。**那不够** ——
Football Field 要的是下面这些。每一项都要能回答「从哪来、哪一期、什么口径」。

### A. 财务报表（已有，需补全）
| 用途 | 要的字段 |
|---|---|
| 收入倍数 | 营业收入（近 3–5 年） |
| EBITDA 倍数 | 营业收入、营业成本、销售/管理/研发费用、折旧摊销 |
| EBIT 倍数 | 上面 + 折旧摊销单列 |
| 净资产法 | 所有者权益合计、归母权益 |
| 净债务桥 | 货币资金、短期借款、长期借款、应付债券、租赁负债、少数股东权益 |

⚠️ **折旧摊销必须单列。** 很多材料把 D&A 塞在费用里或只在附注给 ——
没有它就算不出 EBITDA。**这是当前提取层最大的缺口。**

### B. 股本结构（**招股说明书里的核心**，年报也有）
| 字段 | 用途 |
|---|---|
| 总股本 / 流通股本 | 每股价值 → 股权价值 |
| 摊薄后股数（期权、可转债、限制性股票） | 摊薄后每股 |
| 当前股价 / 发行价 / 要约价 | Football Field 的**基准竖线** |
| 市值（若直接给） | 与股权价值对照 |

⚠️ **市值必须用不复权价 × 当期股数**，不能用现价 × 现股数
（历史股数会因送转变化）。

### C. 报表口径（v0.15 已做）
会计准则（CAS / US GAAP / IFRS）、合并 vs 单体、审计与否、期间、
附注编号。**跨公司可比时口径不一致会被下游当成同一件事**。

### D. 外部数据（可比公司 / 行业）
- 可比公司的市值、EV、EBITDA、收入、增长率
- 基准日（**不能用未来信息** —— 前视偏差）
- 行业：增速、利润率区间、集中度

## ② 假设层：**互动式假设采集**

用户明确要求「跟用户进行互动，得到相应的不同假设」。关键设计：

**事实与假设必须分开**（已有 `Field` / `Assumption` 之分，继续沿用）：
- **事实**（报表里的数）→ 自动填，标来源页码
- **假设**（增长率、折现率、退出倍数）→ **不代填**，只给历史参考区间 + 来源 + 置信度

`valuation/advisor.py` 已经是「假设参谋」的雏形。需要它做的是：
1. 列出这次估值**需要哪些假设**
2. 每个假设给出：历史值、可比公司值、行业值、建议区间、**数据来源**
3. **问用户要**，而不是猜
4. 缺数据就说缺 —— **不许默认值填充**（既有纪律）

---

## ③ 结论层：要产出的东西

### 1. Football Field Chart（**缺，要做**）
把各方法的估值区间画成水平条，叠在一条纵轴上：

```
                       估值区间（每股）
  DCF  ────────████████████──────
  可比公司 ──────────███████████──────
  可比交易 ─────██████████████────────
  LBO  ──────────────────█████████───
  净资产  ─────█████──────────────────
  52周区间 ─────────█████████████─────
                          ┃
                        当前股价
```

**每个区间必须带**：方法的适用性、用的假设、数据来源、置信度。
**区间取敏感性网格的极值，不取点值**（既有纪律）。

### 2. 敏感度分析（引擎已有 `dcf.sensitivity`，要接出来）
- **二维网格**：WACC × 永续增长率 → 每股价值
- 其他维度：收入增速 × 退出倍数、EBIT 利润率 × 折现率
- ⚠️ **跨度超过中值 50% 要报警**（既有纪律）

### 3. 比较报表
- 各方法结果 vs 当前股价（溢价/折价）
- 可比公司的倍数表（带基准日）
- 假设汇总表（每条假设：值、来源、置信度）

### 4. 输出形态（用户已决定，2026-09-16）

> 我觉得生成之后可手动编辑的最好，不过目前初级形态，那种最快生成就用哪个。

**初级形态：HTML**（最快，而且能在桌面端直接看图）。
**最终目标：可手动编辑** —— 大概率是 Excel（用户能打开改假设、改颜色）。

所以结论层**不要和渲染绑死**：先算出一个「估值结果集」的数据结构，
渲染器（HTML / Excel）都从它出发。这样换形态不用重写计算。

## 现在的差距（诚实清单）

| 层 | 有 | 缺 |
|---|---|---|
| 提取 | 三张表 + 勾稽 + 口径 | **D&A 单列**、股本结构、净债务桥的完整性 |
| 假设 | advisor 雏形 | 互动式采集流程、可比/行业数据的注入 |
| 结论 | DCF 敏感性网格、倍数 | **Football Field**、比较报表、输出形态 |

## 顺序

用户明确说：**提取先做准**。所以：
1. 提取层补 **D&A 单列** + 股本结构（招股说明书）
2. 提取层把「失败的材料」修到能过勾稽
3. 再做结论层
