FREEANALYST

01这是什么 · 功能

FreeAnalyst 是一个在本机运行的估值工作台。给它一个标的的材料（年报、审计报告、 CIM、三张表；PDF / Excel / HTML 都行），它做三件事：

  • 报表识别与勾稽校验 —— 认出资产负债表、利润表、现金流量表，跑三条勾稽；认不出就报 「未识别」，不平就拒绝给结论。
  • 假设清单 —— 机器能推的先推出来给你确认（金额单位、会计准则、合并/单体、审计状态、 估值基准日），能确定的字段做成下拉；推不出来的留空，不替你设。
  • 估值计算与报告 —— DCF（含 WACC 逐步推导）、乘数法、Football Field 区间、 敏感性网格、退出倍数交叉验证、对方要价的反向估值。每一项结论都带追溯。

顺带还有一路「问答」：把材料做成本地索引，ask 可以直接问 「调整后 EBITDA 是怎么算的」「回购条款对投资方有利吗」，回答带出处。

02已知限制（能力边界）

这些不是「以后可能」，是现在就做不到的事。写在最前面，免得你在错误的地方信任它。
  • 公开数据源只接了美股 EDGAR 与东方财富股价；A 股 / 港股财务源未接。
  • 扫描件的报表若把合并表与母公司表印在同一页，光学识别会把科目串在一起 → 勾稽不平。它会报警（不静默出错），但需要你把母公司那几页挑出来。
  • 检索是 BM25，没做向量检索；.docx 未支持。
  • 英文界面只覆盖界面文案；引擎输出的报表标签、报告正文仍是中文。
  • 金融业报表（保险 / 银行 / 券商）尚未覆盖。这些行业的科目体系和一般工商业不同 （如保险的「保险服务收入」「赔付支出」「提取保险责任准备金」），词表里没有 → 映射率会很低（实测一份 176 页的保险公司中期报告：利润表 8/76、 现金流量表 7/35）。这时报告会顶出显式警告，点名"关键科目没映射上， 估值结论不可用"，而不是安静地出一份没有结论的报告。
  • 校对责任在人：报告会明说哪些模块没跑、哪些输入缺失，但报出来的不一定穷尽。

04使用哪些模型

一句话：算术绝不用模型。

环节谁来执行为什么
DCF / WACC / 乘数 / 敏感性 / 勾稽校验 纯代码 可复现、可审计：同样输入必得同样结果。编排可以有循环，算术不能有随机。
从材料里抽取（把 OCR 出的文字结构化成表与科目） 大模型 这是语言问题，不是算术问题。
问答与找依据（ask） 大模型 + 本地索引 回答必须带出处，指回材料原文。
  • 模型通过 OpenAI 兼容接口接入，不绑定厂商：Ollama、LM Studio、llama.cpp、 vLLM 或任何兼容网关都可以，换机器不用改代码。
  • 默认指向本机。没有模型也能跑完整估值 —— 只是不做问答。
  • 质量门槛：python3 bench/model_quality.py --models <模型> 或配置页里的按钮。 不合格的模型不参与产出（一票否决）。注意区分：「测不了」不是「不合格」 —— 认证失败/超时是退出码 3，真没达门槛是 2。基线用例集在扩，请以配置页的实测表为准。

哪台机器配哪个模型（用商务本的看这段）

先记住一件事：估值不吃模型。报表识别、勾稽校验、DCF 与乘数计算全是代码执行的； 模型只用在「问答」那一步。所以没有独立显卡的商务本，同样能跑出完整的估值报告。

机器内存建议档位文件大小体验
8 GB3B~4B（Q4 量化）2~3 GB跑得动；问答质量别期待（同档 8B 实测仅 2/5）
16 GB7B~8B（Q4）4~5 GB速度最稳（8B 实测 21 tok/s）；但门槛 2/5，只能当辅助
24~32 GB12B~14B（Q4）8~10 GB本机最优：4/5；代价是慢（14b 实测 6 tok/s，长答案要等）
32 GB+ 或有独显30B 级 MoE（Q4）18~20 GB大不等于稳：30b-a3b 实测 3/5（速度 11.6 tok/s 倒是不慢）
  • 驻留内存实测是文件大小的 1.0~1.14 倍（Q4 量化：qwen3:14b 文件 8.6GB → 驻留 9.4GB）， 另外要给系统与浏览器留约 4GB。内存不足时系统开始用交换分区，整台机器都会卡， 不只是这个工具慢 —— 宁可换小一档。
  • 速度不靠估，靠量：python3 bench/measure_models.py --json bench/measured-local.json。 驻留内存与 tok/s 都取自 ollama 自报的数据；配置页 02 节的「本机实测」表就是它生成的。
  • 材料不用整篇喂给模型：工具是按问题检索片段再问，所以 7B~8B 足以应付。
  • 实在跑不动本机模型，也可以走云端 —— 但每次调用都要单独授权（绑定 主机 + 用途 + 这次发什么）， 并写进审计；代价是那一次的内容离开了本机，机密材料要自己拿捏。

先说一句实话：本机模型现在过不了门槛

质量门槛是用例集全过才算过（一票否决）。实测（bench/gate-local-6.json）： 本机 6 个模型没有一个过 —— 最好的是 qwen3:14b 与 gemma3:12b 各 4/5； 7B~8B 档（hermes3:8b、qwen2.5-coder:7b）只有 2/5；18GB 的 qwen3:30b-a3b 反而只有 3/5。 闭源那边 deepseek-chat 实测 5/5（代价：那一次的内容离开本机）。

所以现在本机的定位是辅助：答案必须带出处（工具会逐条给出处），关键结论人工回原文核对。 不能把本机模型的答复当成产出依据 —— 尤其"某条款是否已锁定""义务落在谁身上"这类判断， 实测正是这些项上翻车。

还没有本地模型？

默认状态下这个工具不需要模型就能出估值报告。想用"读了材料回答问题"，再挑一条路：

路子适合代价
什么都不装（默认）只要估值报告 没有「问答」这一步；其它一步不少
装一个本机模型要问答，又不让材料出本机 下载约 3~5GB，装一次；之后离线可用
走云端本机跑不动，或偶尔问一次 那一次的内容离开本机；每次调用单独授权并进审计

装本机模型就三步：① 到 ollama.com 下载安装（macOS / Windows / Linux 都有）； ② 终端执行一条 ollama pull —— 16GB 内存建议 ollama pull qwen3:8b（约 5GB）， 8GB 建议 ollama pull qwen3:4b（约 2.6GB）； ③ 回来确认：python3 freeanalyst.py models，或在模型设置页点「检测」。 配置页会按你这台机器的内存给出建议命令。

05使用方法

网页向导（最省事）

cd ~/Docs/AI/freeanalyst
python3 freeanalyst.py ui <材料目录>

浏览器会打开 http://127.0.0.1:8765/（只绑本机，同一局域网内别的机器访问不到）。六步： 载入材料 → 报表识别与勾稽校验 → 假设录入 → 估值结论。 （第 3、4 步「行业建议 / 可比公司选取」尚未接入，页面上照实标注。）

载入材料的三种方式：点「选择文件夹… / 选择文件…」调系统原生选择框；或把文件夹从 访达直接拖进卡片；或手工填路径。三种都不复制文件 —— 路径而已，材料留在原地。

命令行

# 材料目录 → 估值报告（两遍：先出问答清单，填完再出报告）
python3 freeanalyst.py appraise <材料目录>
python3 freeanalyst.py appraise <材料目录> --answers <估值问答.txt>

# 材料 → 本地索引 → 带出处的回答
python3 freeanalyst.py ingest <材料目录>
python3 freeanalyst.py ask "调整后 EBITDA 是怎么算的？"

产物统一落在 out/<标的>/（配置、问答清单、报告）。 材料目录只读 —— 工具不往你的材料库里写东西。

06如何调试

命令 / 开关看什么
--trace / --no-trace 打印每一项计算是怎么来的：用了哪条公式、哪个输入、出自哪份材料。
freeanalyst.py audit 查这一次到底有没有东西出网：每一次云端调用与授权记录都在这里。
freeanalyst.py doctor 环境体检：依赖、模型运行时、数据源可达性。
freeanalyst.py models --gate <模型> 模型质量门槛 —— 不合格就一票否决，别用它出数。

python3 -m unittest discover -s tests 全量测试（700+ 项）。改了引擎先跑这个。

最常见的两种「不对」

  • 勾稽不平：先看报告里「N 个科目出现多个取值」的提示 —— 多半是同一页并列了 合并表与母公司表，取值串了。把母公司那几页挑出来单独放，或人工核对所取的是合并列。
  • 单位认不出来：它不会猜（猜错是 1,000 倍级错误），会停下来要你声明。 在第 2 步的下拉里选一个，或自己填。
改了 .py 要重启服务（Python 代码不会热加载）；只改 webapp_page.html 不用 —— 页面每次请求都是现读磁盘的。 服务是旧进程时，页面会自己在顶部提示并给重启命令。

07接入自己的大模型

任何 OpenAI 兼容端点都能接：本地或闭源，改配置即可，不碰代码。

本地（推荐用于机密材料）

  • Ollama：ollama pull qwen3:14b，端点默认 http://127.0.0.1:11434/v1。
  • LM Studio：开启本地服务器，端点通常 http://127.0.0.1:1234/v1。
  • llama.cpp / vLLM：启动时开 OpenAI 兼容模式，填对应 base_url。
  • 配置项：base_url / model（以及需要时的 api_key 环境变量）。 本机端点不需要密钥。

闭源（OpenAI / Anthropic 兼容网关 / DeepSeek / Moonshot 等）

闭源模型有数据风险，必须知情。
你把材料（或材料的片段）发给对方服务器，那一刻它离开了本机。这可能与你的 保密义务、与客户的约定、与个人信息保护的要求冲突 —— 而且对方的数据留存与训练策略 不由你控制。

本工具为此做了三件事，是刻意的设计而不是开关：

  • 不做「一键全局放行」。没有 ALLOW_CLOUD=1 这种粗暴开关 —— 每一次云端调用都要 按次授权（绑定主机 + 用途 + 内容描述），授权本身进审计。
  • privacy.py 是唯一的跨域出口：机密域只放行回环地址， 外发的值与本地语料逐字比对。
  • 可查：python3 freeanalyst.py audit 会告诉你这一次到底有没有东西出网。

建议的做法：机密标的只用本地模型；闭源模型用在公开材料（如上市公司年报） 或脱敏片段上。一句话原则 —— 模型的自由度越高，能碰到的数据就要越少。

01What this is · Features

FreeAnalyst is a valuation workbench that runs on your own machine. Point it at a target's materials (annual report, audit report, CIM, the three statements; PDF / Excel / HTML), and it does three things:

  • Statement extraction and reconciliation — identifies the balance sheet, income statement and cash flow statement and runs three reconciliation tests. What it cannot identify is reported as not identified; when a test fails it refuses to give a conclusion.
  • Assumption register — anything the machine can derive is derived and shown for confirmation (reporting unit, accounting basis, consolidated vs standalone, audit status, valuation date), with closed sets offered as dropdowns. What it cannot derive is left blank — it will not set assumptions for you.
  • Valuation and report — DCF (with WACC derivation), multiples, a football-field range, sensitivity grids, exit-multiple cross-checks and reverse valuation against an asking price. Every conclusion is traceable.

There is also a Q&A path: index the materials locally and ask ask questions such as how adjusted EBITDA is defined, with citations.

02Known limits

These are not roadmap items — they are things it cannot do today.
  • Public data sources cover US EDGAR and East Money prices only; A-share / HK financial sources are not wired.
  • If a scanned report prints the consolidated and parent-only statements on the same page, OCR interleaves the line items and reconciliation will fail. It raises a flag rather than failing silently, but you must separate the parent-only pages.
  • Retrieval is BM25; no vector search. .docx unsupported.
  • The English interface covers interface copy only; engine output remains Chinese.

04Which models are used

In one line: arithmetic never goes through a model.

StepExecuted byWhy
DCF / WACC / multiples / sensitivity / reconciliation Plain code Reproducible and auditable: identical inputs give identical outputs.
Extraction (structuring OCR text into tables and line items) LLMA language problem, not an arithmetic one.
Q&A with citations (ask) LLM + local indexAnswers must cite the material.
  • Models are reached through an OpenAI-compatible endpoint — no vendor lock-in (Ollama, LM Studio, llama.cpp, vLLM or any gateway).
  • Defaults to local. Valuation runs fully without any model; only Q&A needs one.
  • Quality gate: python3 bench/model_quality.py --models <model>, or the button on the settings page. A model that fails is not used in production output. Note the distinction: "could not run" is not "did not qualify" — an auth failure or timeout exits with code 3, a real miss with 2. The case set keeps growing; trust the measured table on the settings page.

Which model fits which machine (read this if you use a business laptop)

First, the important part: valuation does not need a model. Statement recognition, articulation checks, DCF and multiples are pure code; models are used for Q&A only. So a business laptop with no GPU can still produce the full valuation report.

Machine RAMSuggested sizeFile sizeExperience
8 GB3B–4B (Q4)2–3 GBRuns; don't expect much from Q&A (the 8B tier measured just 2/5)
16 GB7B–8B (Q4)4–5 GBFastest tier (8B measured 21 tok/s) — but the gate score is 2/5: assistant only
24–32 GB12B–14B (Q4)8–10 GBBest locally: 4/5, at a price — 14b measured 6 tok/s (long answers make you wait)
32 GB+ or a discrete GPU30B-class MoE (Q4)18–20 GBBigger is not steadier: 30b-a3b measured 3/5 (11.6 tok/s, so it is fast)
  • Resident memory measures 1.0–1.14× the file size (Q4: qwen3:14b is 8.6 GB on disk, 9.4 GB resident), and the OS still needs ~4 GB. When RAM runs out the machine starts swapping and everything crawls — drop a size rather than thrash.
  • Measure speed, don't guess: python3 bench/measure_models.py --json bench/measured-local.json. Resident memory and tok/s both come from ollama's own reporting; the "measured on this machine" table in section 02 of the settings page is generated by it.
  • The model is not fed whole documents: the tool retrieves passages per question, so 7B–8B is enough.
  • If nothing runs locally, cloud models are available — but every single call needs its own consent (host + purpose + what is being sent) and is audited; the price is that this one call's content leaves the machine. Judge that for confidential material yourself.

Straight talk: no local model passes the gate today

A model passes only if every case passes (a single miss is fatal). Measured (bench/gate-local-6.json): none of the six local models passes — the best are qwen3:14b and gemma3:12b at 4/5; the 7B–8B tier (hermes3:8b, qwen2.5-coder:7b) sits at 2/5; and the 18 GB qwen3:30b-a3b does worse at 3/5. On the closed-source side deepseek-chat scored 5/5 (at the price of that call's content leaving the machine).

So treat local models as assistants: answers must carry citations (the tool provides them per line) and key conclusions need a human check against the source. Do not use a local model's answer as the basis for a figure — the failures land exactly on judgements like "is this clause locked?" and "whose obligation is this?".

No local model yet?

By default this tool needs no model at all to produce a valuation report. If you want question-answering over the materials, pick one of three paths:

PathFitsPrice
Install nothing (default)You only need the report No Q&A — every other step is unaffected
Install one local modelYou want Q&A and materials must stay on this machine A one-off download of roughly 3–5 GB; works offline afterwards
Use a cloud modelNothing runs locally, or you only ask occasionally That call's content leaves the machine; per-call consent, audited

Installing a local model is three steps: (1) download Ollama from ollama.com (macOS / Windows / Linux); (2) run one ollama pull — on 16 GB of RAM, ollama pull qwen3:8b (about 5 GB); on 8 GB, ollama pull qwen3:4b (about 2.6 GB); (3) confirm with python3 freeanalyst.py models, or press "detect" on the model settings page. The settings page suggests a command based on your machine's RAM.

05How to use

Web workbench

cd ~/Docs/AI/freeanalyst
python3 freeanalyst.py ui <materials>

Opens http://127.0.0.1:8765/ (loopback only — other devices on the same network cannot reach it). Four working steps: load materials → extraction and reconciliation → assumptions → conclusion. (Industry guidance and comparable selection are not wired and are labelled as such.)

Three ways to load materials: the native folder/file picker, dragging a folder in from Finder, or typing a path. None of them copies anything — only a path travels.

Command line

python3 freeanalyst.py appraise <materials>
python3 freeanalyst.py appraise <materials> --answers <answers.txt>
python3 freeanalyst.py ingest <materials>
python3 freeanalyst.py ask "How is adjusted EBITDA defined?"

Artifacts land in out/<target>/. The materials folder is treated as read-only.

06Debugging

Command / flagWhat it tells you
--trace / --no-trace Prints how each figure was derived: formula, input, and source material.
freeanalyst.py audit Whether anything left this machine — every cloud call and authorisation.
freeanalyst.py doctor Environment check: dependencies, model runtime, data-source reachability.
freeanalyst.py models --gate <model> Model quality gate — a failing model must not produce figures.
python3 tools/check_ui.py Interface self-check: element ids, zh/en key parity, service/page contract, logo geometry.
python3 -m unittest discover -s tests Full test suite (700+).

The two most common problems

  • Reconciliation fails: look for the "N line items carry more than one value" note — typically consolidated and parent-only statements sharing a page.
  • Reporting unit undetermined: it will not guess (a wrong unit is a 1,000× error); it stops and asks you to declare it.
Restart the service after changing any .py — Python code is not hot-reloaded. Only webapp_page.html is re-read on every request. When the service is stale, the page detects it and shows the restart command.

  • LM Studio: start the local server, usually http://127.0.0.1:1234/v1.
  • llama.cpp / vLLM: enable OpenAI-compatible mode and set base_url.

Closed-source (OpenAI / Anthropic-compatible gateways / DeepSeek / Moonshot …)

Closed-source models carry data risk, and you must be aware of it.
The moment you send materials (or fragments of them) to a provider's servers they leave this machine. That may conflict with your confidentiality obligations, client agreements and data-protection requirements — and retention/training policies are outside your control.

Three deliberate design choices address this:

  • No global "allow cloud" switch. There is no ALLOW_CLOUD=1 escape hatch: every cloud call requires a per-call authorisation (host + purpose + content description), and the authorisation itself is audited.
  • privacy.py is the only egress path: the confidential domain permits loopback only, and outbound values are compared verbatim against the local corpus.
  • Verifiable: python3 freeanalyst.py audit reports what did or did not leave the machine.

Suggested practice: confidential targets on local models only; use closed-source models for public materials (e.g. listed-company annual reports) or redacted excerpts. One principle: the more freedom a model has, the less data it should see.
