# FreeAnalyst

**Open source. Air gapped. Off at six.**

自由分析师 · 免费分析师

---

一级市场投资的尽调 agent。完全跑在你自己的机器上——你的 CIM、会议纪要、估值逻辑、
条款清单，一个字节都不离开这台电脑。

## 为什么叫 FreeAnalyst

`free` 有两个意思，两个都成立。

**自由。** 它替你把该读的材料读完、该核对的数据核对完，把时间还给你。
九点到六点，也能做完一天的尽调。

**免费。** 没有订阅，没有席位费，没有 token 账单。模型跑在你自己的机器上，
工具是开源的。一个免费的分析师，全天候待命。

## 两个域：机密域不出网，公开域拿不到机密

程序要联网（抓可比公司、查公开数据），但材料不能出去。这两件事怎么同时成立？

**靠能力隔离，不靠内容过滤。** 内容过滤做不到——你无法判断一段出境文本里有没有
夹带机密：

> "标的企业A、收入1.83亿、增速17.9%、行业只有三家可比"
>
> 这组数字本身就是指纹，把公司名替换成"A"没有用。

```
┌─ 机密域 ──────────────────┐        ┌─ 公开域 ──────────────────┐
│ corpus / root / 本地模型   │        │ 白名单数据源               │
│ guard.py：只放行 localhost │   ✕    │ net.py：只放行白名单主机    │
│ 审计日志：外部主机 无       │◄─────► │ 审计日志：只有公开查询词    │
└───────────────────────────┘        └───────────────────────────┘
                    ↑
            privacy.py：唯一允许跨域的入口
            出境值与本地语料逐字比对，重合即拒
```

三层防护，按重要性排序：

| 层 | 机制 |
|---|---|
| **1. 代码路径隔离** | 公开域函数只接受代码/日期/指标名，调用点写在读不到语料的代码里 |
| **2. 语料重叠检查** | 出境值与语料逐字比对（归一化后，改写标点绕不过） |
| **3. 格式检查** | 长度、字符集、换行、本地引用 —— **实测证明这层不足，只是防误伤** |

**一个诚实的记录**：格式检查曾让一段 45 字的完整语料段落顺利通过。
这个局限被固定成了一条测试（`TestFormatChecksAreNotEnough`），
免得后来的人以为格式检查够了。

**标的公司名本身也是机密。** 查 "宁波精塑 可比公司" 会在公开数据源留下
"你在看这家公司"这个事实。禁名表放在 `root/privacy-blocklist.txt`。
合规的替代方式是**用行业代码，不用公司名**。

## 早期项目：DCF 和乘数法都用不了的那一段

pre-revenue 的项目没有现金流，也没有 EBITDA。硬套的结果是分母为零或负数，
**算出来的数毫无意义，而且不会报错。**

所以早期项目要用另一套逻辑 —— 它估的不是现金流，是**风险和里程碑**。

```bash
python3 value.py examples/early-stage-demo.json
```

`value.py` 看到配置里有 `early_stage` 段就自动走这条流程，不用记两个命令。

| 方法 | 回答的问题 |
|---|---|
| **Berkus** | 去掉了几个风险？ |
| **Scorecard** | 比市场上的同类好还是差？ |
| **VC 法** | 要赚到目标回报，今天最多能付多少？ |
| **First Chicago** | 分情景看，概率加权是多少？ |

**三者的哲学完全不同，所以它们给出不同的数不是错误，是信息。**
演示里的差额是 189%，这本身就是该写进备忘录的结论。

### 两个锚点没有默认值

| 锚点 | 为什么 |
|---|---|
| Berkus 的「每因素封顶值」 | 原版是 **1990 年代美国西海岸的 50 万美元**。照抄到别的年份、别的地区是错的 |
| Scorecard 的「区域基准 pre-money」 | 是外部事实，算不出来。而且**市场冷热差一年，定价能差一半** |

给它们配"合理默认值"是最糟的设计：你会拿到一个看起来正常的数，
而它其实来自别人的市场、别人的年份。**所以不给就报错。**

### 稀释那一步最容易漏

```
今天占 20%  ≠  退出那天还占 20%
```

后续每轮都会稀释。忽略稀释会让 pre-money **偏高**，偏高幅度正好等于被稀释的部分。

而且方向反直觉：**稀释让投前估值变低，不是变高。**

> 投资者要 20% 的退出股权。若有 25% 未来稀释，今天必须占到 26.67%。
> 为同样的钱拿到更多股权 → 投后更低 → 投前更低。

这条写反了不会报错，只会安静地给出错的数。

### 有报价就跑反向

把「贵不贵」翻译成「要涨到多大」：

```
按这个价格，公司要在 5 年内做到 242,857 万元 的退出价值，即年化 70.2%。
**谈论这个数是否可信，比谈论估值高低有用得多。**
```

反向结果**不参与多方法差额** —— 它输出的不是估值，是「需要多大的退出」。
混进去算差额会得到一个毫无意义的数，而且看起来还挺像回事
（实测它把差额从合理的量级拉到了 199%）。

## 数据源：先接免费的官方源

**全部走公开域闸门，拿不到本地语料。**

| 市场 | 源 | 状态 |
|---|---|---|
| 美国上市公司 | **SEC EDGAR** | ✅ 已接入 |
| A 股 / 港股 | AKShare / Tushare | ⬜ 待接入 |
| 股价（任何市场） | — | ⚠️ **缺口，见下** |

### SEC EDGAR 为什么值

免费、无需 API key、无需注册，而且是**官方结构化数据**（XBRL）——
不用让大模型去"读"年报。

```bash
export SEC_USER_AGENT="你的机构名 你的邮箱@example.com"   # 必须带邮箱，否则 403
```

```python
from datasources import sec_edgar as se

cik = se.ticker_to_cik("AAPL")                    # 代码 → CIK
facts = se.company_facts(cik)                     # 全部 XBRL 数据
se.annual_series(facts, "Revenues")               # 年度序列
se.derive_ebitda(facts, "2025-12-27")             # 推算 EBITDA
se.frames("Assets", "CY2024Q4I")                  # 一次拿 6,000+ 家公司
```

`frames` 是可比公司筛选的现成答案 —— **一次调用返回同一科目、
同一期间、所有申报人的值。**

### 三个已实测确认的坑

| 坑 | 症状 | 处理 |
|---|---|---|
| **不带邮箱** | HTTP 403，且 SEC 不解释原因 | 本地先报错并给指引 |
| **请求了 gzip 不解压** | `UnicodeDecodeError: 0x8b`，看着像编码问题 | 按魔数解压 |
| **年度值和季度值混在一起** | 数据不报错，但季度值被当成年度值 | 按 start→end 时长分档 |

第三个坑最阴险。同一个标签、同一个期末挂着多条数据，区别在时长：

```
FY2025 营收   2024-09-29 → 2025-09-27   364 天   ← 年度
同期单季      2026-03-29 → 2026-06-27    90 天   ← 季度
同期累计      2025-09-28 → 2026-06-27   272 天   ← 9 个月 YTD
```

**实测 Apple 的营收标签有 117 条数据点，只有 21 条是年度值。**

### 标签会废弃，数据会静默停在旧年份

Apple 的 `Revenues` 标签数据**停在 2018 年** —— 它后来换用了
`RevenueFromContractWithCustomerExcludingAssessedTax`。
只试一个标签，拿到的是八年前的数，而且不报错。

所以推算科目（营收、EBITDA）都按优先级试多个候选标签，
**返回用了哪个标签**，让人能核对。

### 已知缺口：EDGAR 没有股价

| 能算 | 不能算 |
|---|---|
| EBITDA、收入、净利、总资产 | 市值 |
| 跨公司同年份横向对比 | 企业价值 EV |
| 每股收益、股数 | **EV/EBITDA** |

**EDGAR 有财报，没有市值。** 要做市值倍数必须再配价格源。
这一层留了位置，但没有假装它能用。

## 快速开始

```bash
# 1. 装一个本地模型（Ollama 为例）
ollama pull qwen2.5-coder:7b

# 2. 把材料放进去（换成你自己的路径）
cp ~/deals/某个标的/*.txt corpus/

# 3. 入库
python3 freeanalyst.py ingest corpus

# 4. 提问
python3 freeanalyst.py ask "调整后 EBITDA 是怎么算的？回购条款对投资方有利吗？"

# 5. 查审计
python3 freeanalyst.py audit
```

**零第三方依赖。** 只需要 Python 3.10+ 和一个本地模型。

模型层用 OpenAI 兼容接口，不绑定后端——Ollama、LM Studio、vLLM、llama.cpp
都可以，换机器不用改代码。

## 估值引擎

```bash
python3 value.py examples/valuation-demo.json
```

**纯代码计算，不用模型算数。** 估值是确定性数学——让大模型去算会算错，而且
算错了你查不出来。模型在这个流程里只做两件事：把材料抽成数字、给假设找依据。

已实现：

| 模块 | 内容 |
|---|---|
| **WACC / CAPM** | Hamada 去杠杆/再加杠杆、规模溢价、国家风险溢价，逐项带来源 |
| **DCF（FCFF）** | 逐年驱动因子、永续增长法与退出倍数法双终值、二维敏感性矩阵 |
| **反向估值** | 从对方要价反推隐含永续增长率 —— 尽调里最有用的一件工具 |
| **乘数法** | EBITDA / SDE / 收入；可比公司分位数汇总 |
| **SDE 构建** | 从净利润倒推到 Seller's Discretionary Earnings，逐项调整可追溯 |

三条纪律贯穿全部代码：

1. **每个假设必须带来源和置信度。** 没有来源的假设是隐性炸弹——它不报错，
   但会让结果偏掉，事后无从判断错在哪。
2. **缺数据就说缺。** 桥梁项（少数股东权益、非经营性资产）缺失时按 0 计算，
   但会同时出现在「数据缺口」清单里。**禁止静默填充。**
3. **算不出来就报错。** 核心输入缺失、永续增长率 ≥ WACC、基数为负——
   这些都直接拒绝计算，不给出一个看起来正常的错数字。

测试用手算的已知答案验证（26 项），不是"跑通了"，是"算对了"：

```bash
python3 -m unittest tests.test_valuation -v
```

**需求基线见 [`docs/valuation-spec.md`](docs/valuation-spec.md)。**
它记的不是"我们要做什么功能"，而是"**什么情况下这个估值才是可信的**"——
功能可以增删，那些条件不能绕过。新增估值相关功能前，对照它的检查清单过一遍。

## 开源框架 + 你的私有资产

这个项目刻意分成两半：

```
开源（进 git）                    私有（永久 gitignore）
├── guard.py        出网闸门      ├── root/      你填好的判断框架
├── retrieval.py    本地检索      ├── corpus/    你真实的 CIM 和纪要
├── freeanalyst.py  CLI           └── index/     你本地的索引
├── root-templates/ 空白模板
└── tests/
```

`root-templates/` 里是投资判断框架的骨架——基金身份、赛道观点、红旗清单、
筛选阈值、条款立场、备忘录模板。

**填好的版本永远不进 git。** 原因很简单：单个 deal 泄了是损失一笔生意，
那套框架泄了，基金就没有护城河了。

## 为什么机密不只是"公司名"

大多数人做保密设计，想的是"别让外人看到标的企业叫什么"，所以他们的办法是
把公司名替换成"标的企业A"再送到云端。

**这条路是错的。** 因为机密不在名字，在语义组合——收入、增速、EBITDA 率、
行业里只有三家可比标的、我们正在看其中一家。这组数字本身就是指纹。

而真正值钱的，是**你的判断框架**。所以 `root-templates/` 那套东西，
比任何单个 deal 都更需要保护。

## 质量门槛：本地模型够不够格？

"能不能跑"和"能不能用"是两件事。小模型能让流程跑通，但会犯三类致命错误：

| 错误 | 为什么致命 |
|---|---|
| **主体搞混** | 把实控人的个人回购义务说成公司的财务压力 → 结论反向 |
| **跨文档冲突检测不出来** | CIM 说条款已定，访谈纪要里对方其实有保留 → 尽调的全部价值就在这 |
| **编造内容** | 材料里没有的文件，它替你把结论写出来 → 比没有助手更危险 |

所以我们不靠感觉换模型，靠一组**固定会失败的用例**：

```bash
python3 bench/model_quality.py --models qwen2.5-coder:7b --show-answers
```

```
  [失败] 主体识别
        ↳ 把个人义务说成公司负担：「公司面临较大的财务压力」
  [失败] 跨文档冲突
        ↳ 未引用访谈纪要 —— 说明未做跨文档比对
  [通过] 格式遵循
  [失败] 拒答幻觉
        ↳ 结论节编造了材料中不存在的内容：「已闭环」

  小计：1/4 —— 未达门槛
```

**全绿才算够格进生产。**

判分刻意做得比关键词匹配严格：**按节解析**（某一节写得漂亮救不了另一节说错话）、
**来源覆盖**（跨文档那条必须同时引用两边，只引一边说明压根没比对）、
**语义模式**（覆盖整个表述族，而不是死盯一个固定说法）。

如果你要换模型，**先用一个已知不合格的模型跑一遍**——如果它全过，说明评测失效了，
这比模型不合格更严重。
